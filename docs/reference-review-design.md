# 정답 검토 도구 화면 설계

사용자는 고정된 300개 원음을 들으면서 제공 정답을 확인하는 검토자다. 기존 독립 평가 서식과 비공개 300건 검토표를 작업 흐름의 기준으로 삼았다. 모델 결과를 읽거나 비교하는 화면은 포함하지 않는다.

주 작업은 한 항목의 원음과 정답 확인이며 주 동작은 **확인 완료 · 다음**이다. 초기 화면은 진행/검토자, 원음, 제공 정답과 편집, 확인·이동의 네 작업 묶음으로 구성한다. 보류 메모와 내보내기는 부차 동작으로 둔다. 검토 목록은 데스크톱의 좁은 왼쪽 열, 모바일에서는 접힌 목록으로 제공한다.

시스템 한글 글꼴과 회백색 배경, 흰 편집 면, 진한 녹색 주 동작을 사용한다. 색·간격은 CSS 변수로 관리한다. 수치 대시보드, 임의 파형, 장식 애니메이션은 넣지 않는다. 상태는 색과 함께 텍스트로 표시하고 입력/버튼에 명시적인 이름과 키보드 초점을 제공한다.

로딩은 항목 준비/저장 중 상태로 표시한다. 저장 실패·버전 충돌은 입력을 유지하고 이동을 멈춘다. 한국어 조합 중에는 초안 저장과 완료 단축키를 실행하지 않는다. 전체 완료는 실제 저장된 완료 상태만 집계하며 보류·초안은 완료 수에 포함하지 않는다.

확인 기준은 원음 재생·이동, 수정 초안 저장·재진입, 명시적 완료 저장, 다른 검토자 격리, 버전 충돌 방지, 모바일 넘침 없음과 모델 출력 비노출이다. 실제 300건에는 자동화로 임상 판정을 채우지 않는다.

## 반복 클릭 감소

2026-11-19: 재생 → 청취 확인 체크 → 완료 클릭을, 첫 `Space` 뒤 **`Enter`로 명시적 청취·정답 확인과 다음 이동**하는 흐름으로 바꾼다. 다음 원음은 자동 재생하지만 정답을 자동 완료하지 않는다. 원래 제공 정답을 유지한 채 확인할 때는 항목당 확인 한 번만 필요하다.

`Space` 재생/멈춤, `R` 처음부터, `E` 편집, 편집 중 ⌘/Ctrl+Enter를 제공한다. 편집창에서는 일반 Space·Enter와 한글 조합을 가로채지 않는다. 입력 후에는 초안 자동 저장을 유지하며 저장 실패 시 이동을 멈춘다. 다음 항목의 초점은 편집창 대신 검토 영역에 두어 일반 Enter가 줄바꿈으로 들어가지 않게 한다. 미디어·입력·버튼 자체의 키보드 동작은 보존한다.

기존 색·글꼴·레이아웃을 유지하고 완료 동작을 하단 고정 영역에 둔다. 편집창을 짧게 하고 별도 청취 체크박스를 없애 반복 스크롤·포인터 이동을 줄인다. 자동 재생은 첫 사용자 재생 이후에만 시작하며 해제할 수 있다. 차단 시 재생 안내를, 로딩 시 비활성 입력을, 저장 실패 시 보존된 입력과 오류를 표시한다. 모델 출력과 다른 검토자 결과는 계속 표시하지 않는다.

확인: `node --test tests/review_ui_keyboard.test.cjs`의 4개 시나리오 통과. 실제 브라우저의 별도 합성 표본에서 Space 재생, Enter 확인·다음 자동 재생, E 편집, 일반 Enter/Space 입력 보존, Ctrl+Enter 저장과 SQLite 청취 확인/재생 기록을 확인했다. 마지막 항목 이후 추가 Enter는 새 완료 기록을 만들지 않는다. 1280×900·390×844 화면에서 가로 넘침 없이 하단 동작을 확인했다. 실제 검토 화면은 저장된 진행 상태와 새 UI를 읽기 전용으로 확인했으며, 물리 키보드의 수동 한글 IME 조합·실제 항목의 정답 판정은 자동 검증하지 않았다.
