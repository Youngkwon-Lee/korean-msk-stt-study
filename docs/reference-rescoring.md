# 300건 검토 후 수정 정답 재평가

고정한 `reference_review_substudy` 전부를 완료한 뒤 기존 정확도 단계의 Qwen3-ASR 1.7B·GPT-Transcribe 출력을 **수정 정답으로 다시 채점**한다. 모델을 재호출하지 않으며 GPU·외부 API·새 비용은 필요하지 않다. 검토 앱은 그대로 유지하고 별도 로컬 분석기를 수동 실행한다. 모델 출력은 검토 화면에 추가하지 않는다.

## 실행과 완료 조건

설정된 비공개 작업 폴더의 `rescore-reference-review.command`를 실행한다. 이 실행 파일은 저장된 검토 DB와 고정된 두 모델 출력 경로·해시를 사용한다. 감시 작업이나 자동 게시 기능은 없다.

- **300/300건이 `reviewed` 상태**여야 한다. 미검토·초안·보류가 하나라도 있으면 완료 수만 알리고 중단한다. 청취 확인·재생 기록·유효한 수정 정답도 검사한다.
- SQLite를 읽기 전용 트랜잭션으로 읽어 한 시점의 정답·버전·청취 확인을 고정한다. 다른 검토자의 기록을 섞지 않는다. 원본 manifest와 DB를 수정하지 않는다.
- 명세 SHA-256, 원래 정답 지문, 선택 순서, 음성 해시, 두 모델 제공자, 원래 용어 주석, 모델 설정·개별 출력의 고정 지문을 대조한다. 빠진 결과·변경된 출력·다른 명세를 거절한다.
- 실행마다 새 비공개 결과 폴더를 만든다. 나중에 정답을 다시 수정하면 같은 실행 파일로 새 버전을 만들며 과거 결과를 덮어쓰지 않는다.

다른 환경에서는 표준 라이브러리만으로 다음 명령을 사용한다. `--qwen-run`과 `--gpt-run`에는 **accuracy** 디렉터리를 지정하며 별도 latency 반복 출력을 사용하지 않는다. 두 디렉터리는 선택 300건과 원래 `run.json`만 있어도 된다.

```sh
python3 -B scripts/rescore_reviewed.py \
  --manifest /path/to/private/run-ready-manifest.json \
  --expected-manifest-sha256 EXPECTED_MANIFEST_SHA256 \
  --review-db /path/to/private/reviews.sqlite3 --reviewer reviewer-1 \
  --qwen-run /path/to/private/qwen-accuracy \
  --gpt-run /path/to/private/gpt-accuracy \
  --expected-qwen-sha256 EXPECTED_QWEN_RECEIPTS_SHA256 \
  --expected-gpt-sha256 EXPECTED_GPT_RECEIPTS_SHA256 \
  --annotations /path/to/private/literal-term-annotations.json \
  --out private-runs/reviewed-reference/new-analysis
```

`--check-ready`를 쓰면 모델 파일을 읽거나 결과를 생성하지 않고 검토 완료 수만 JSON으로 반환한다. 준비가 안 됐을 때 종료 코드는 2다. 고정 지문은 `load_outputs()`가 명세의 선택 순서대로 설정 파일 및 개별 출력의 원래 바이트를 해시한 값이다. 제공자의 출력 파일이 달라지면 임의로 지문을 새로 정하지 말고 입력 변경 원인을 확인한다.

## 생성되는 논문용 표

| 표 | 내용 |
|---|---|
| 1 | **같은 300건**의 제공 정답/검토 정답 기준 CER, 편집 오류/정답 글자 수, 완전 일치, 지정 의료 용어 문자열 오류/출현 수, 전사 기술 실패 |
| 2 | 수정 정답 기준 `staff`·`patient` 라벨별 CER·문자열 오류와 분모 |
| 3 | 수정 정답에서 용어 범주별 출현 수·두 모델 오류 수/비율 |
| 4 | GPT−Qwen의 대응 CER·문자열 오류율 차이(%p), 원래 정답 문구 그룹별 재표집의 기술적 95% 범위 |

비율의 분모는 항목별 평균이 아니라 **오류 합계/정답 글자 또는 용어 출현 합계**다. 기술 실패가 있으면 두 모델 모두 성공한 같은 집합에서 수정 전후를 비교하고, 실패 수는 전체 선택 표본을 분모로 별도 보고한다. 0분모는 0%로 꾸미지 않고 `NA`로 표시한다.

표는 `tables.md`, `tables.csv`, `tables.tex`로 생성한다. CSV는 표 제목·헤더·내용을 빈 행으로 구분해 Excel에서 열 수 있다. LaTeX 표는 `graphicx` 패키지의 `resizebox`를 사용한다. `aggregate.json`은 수치·분모·입력 지문·분석 코드 지문을, `methods.md`는 방법·정답 변경 개수·한계를 담는다. 생성된 파일은 모두 비공개 후보이며 자동 업로드하지 않는다.

`review-snapshot.json`에는 실제 정답·현재 저장 버전·청취 확인이, `private-scores.json`에는 선택 순서의 개별 점수가 들어 있다. 전체 수정 이력은 원래 검토 DB에 보존한다. **이 두 파일과 DB·원음·모델 출력은 공개하지 않는다.** 논문/공개 레포로 옮길 때에는 집계·표·방법 파일만 별도로 내용 검토한다.

## 용어 평가와 해석 범위

기존 25개 유형의 사전을 유지한다. 수정 정답에서 다시 용어를 찾아 **출현 위치와 분모를 재생성**하고 문자 정렬로 보존 여부를 계산한다. 원래 정답의 위치나 기존 699회 분모를 수정 정답에 재사용하지 않는다. 따라서 수정 전후의 용어 분모는 달라질 수 있다. 모델 출력을 보고 사전·정규화·정답을 바꾸지 않는다.

이 값은 지정된 의료 관련 **문자열 보존 오류**다. 문맥 적격성·동의어·부정·좌우·수치·임상적 심각도의 전문가 판정은 포함하지 않는다. 짧은 다의어가 포함되므로 임상적 의미 오류율·안전성으로 보고하지 않는다. 재표집은 seed 20261117, 기본 2,000회이며 원래 정답의 같은 정규화 문구를 한 블록으로 유지한다. 용어 분모가 0인 재표집은 용어 범위에서 제외하고 유효 횟수를 JSON에 남긴다. 화자 의존성을 보정한 모집단 신뢰구간이나 p값은 생성하지 않는다.

**300건 재평가를 1,800건 전체의 독립 검토 완료로 표현하지 않는다.** 기존 1,800건 결과와 속도 결과는 보존한다. 이 분석은 정답 변경에 대한 하위표본 민감도 분석이다. 현재 분석기는 검토자 1인의 완료 자료를 사용하며, 연구계획의 두 번째 독립 검토·불일치 합의는 별도 미완료로 남긴다. 최종 합의 정답은 출처·버전을 분리해 추가 절차로 고정해야 하며 한 검토자의 ID를 합의 정답으로 바꿔 부르지 않는다.

## 검증

합성 자료로 미완료/초안/보류 차단, 검토자 분리, 수정에 따른 CER·용어 분모 변화, 성공 대응 집합, 0분모, 명세·해시·청취 확인 오류, 고정 출력 변경 거절, CSV/Markdown/LaTeX 생성과 비공개 자료 비노출, 과거 결과 덮어쓰기 방지를 확인한다. 실제 300건을 자동 완료하거나 정답을 AI로 대신 판정하지 않는다.
